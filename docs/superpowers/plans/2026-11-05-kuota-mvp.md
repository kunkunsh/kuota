# Kuota v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a reliable local-first TypeScript quota library, a CLI, and UniView TUI on HK's Mac mini, with a tested Codex app-server provider, then extend to Claude and agy.

**Architecture:** Workspaces divide portable schema/normalization, local provider adapters, scriptable CLI and an optional UniView React TUI. Provider errors are isolated. Auth and provider transports remain behind Effect services; there is no cloud backend or daemon for v0.1.

**Tech Stack:** TypeScript 5.9+, Node 24/Bun, `vite-plus` project-local v1.5+, Effect 3.x, `@effect/cli` 0.77.x, Vitest through `vp test`, UniView `@uniview/tui-react` and `@uniview/tui-core` 0.0.3+, React 19.

**Spec:** `docs/specs/2026-11-05-kuota-design.md`

## Global Constraints

- Work on `/Users/hk/Dev/kuota` (Mac mini). Existing empty Git repository; no blind overwrite.
- Use project-local Vite+ (`bun run test` => `vp test`); do not install a global `vp` executable.
- Real user auth is testing context, not test fixtures; never print, commit or upload local credentials, cookies, raw local server handshake or account email.
- `--json` is one complete valid JSON value on stdout. Human errors go to stderr. Never use a TUI from noninteractive commands.
- Do not claim Claude/agy quota support until an actual integration test succeeds; distinguish inability to probe from zero remaining.
- MVP supports macOS first, while core contracts are portable and cleanly package-scoped.
- No public GitHub push or npm publish in this task without explicit confirmation.

## Review Focus

1. A provider's malformed percentage is not displayed as 0% or silently clamped to an apparent valid reading — tests in Task 1.
2. A spawned app-server that emits multiple notifications or never replies doesn't hang the CLI — tests in Task 2.
3. A provider exception does not hide healthy providers in a bulk refresh — tests in Task 3.
4. `--json` stdout remains parseable and credential-free on partial auth failure — tests in Task 4.
5. TUI accidentally launched from non-TTY or terminal not restored on failure — tests in Task 5.

### Task 2: Codex app-server adapter, transport, and fixtures

**Interfaces:** `parseCodexRateLimits(unknown): QuotaSnapshot`, `readCodex(options?: { timeoutMs?: number; binary?: string }): Effect.Effect<QuotaSnapshot, ProviderError>`. The transport launches existing `codex app-server` and requests `account/rateLimits/read` after initialization.

- [ ] Step 1. Inspect installed Codex help/version; invoke its real app-server protocol once via a bounded throwaway read, recording redacted method names and response shapes, not raw access tokens. Expected: protocol and output shape documented, or explicit readiness blocker.
- [ ] Step 2. Write failing fixture tests for rate-limit `primary`/`secondary`, missing reset times, inactive account, unexpected notification before reply, malformed JSON, error response and timeout. Expected: FAIL (missing parser/transport).
- [ ] Step 3. Implement a newline-delimited JSON-RPC subprocess adapter with unique IDs and total timeout; do not use a shell string, no raw payload logging. Expected: focused tests PASS.
- [ ] Step 4. Run a single real `readCodex` against Mac mini installation and check only _sanitized_ status/percent/reset fields; don't assume a logged-in session. Expected: valid success or clear typed failure, never fabricated data.
- [ ] Step 5. Run all suite/typecheck and commit `feat(providers): read Codex quota via app-server`.
